# Internationalisation (i18n) — Transloco

Stellar utilise [Transloco](https://jsverse.github.io/transloco/) pour tout le texte destiné à
l'utilisateur. L'i18n natif d'Angular (`$localize`, `.xlf`, attributs `i18n`, `ng extract-i18n`)
n'est utilisé nulle part dans ce codebase.

## Synthèse

**Exécution locale :** rien de particulier à configurer — `public/assets/config/app-config.json`
est inclus dans le dépôt avec `defaultLang: "fr"` et est servi tel quel par `npm run start` /
`ng serve`. Le changement de langue peut se faire à l'exécution depuis le sélecteur de langue de
l'interface, ou bien en modifiant ce fichier manuellement pour changer la langue par défaut.

**Exécution avec Docker :** la langue par défaut est un argument de build inclus dans l'image ; la
modifier nécessite de reconstruire l'image :

```bash
docker build --build-arg DEFAULT_LANGUAGE=en ...
```

Voir [Langue par défaut configurable au moment du build](#langue-par-défaut-configurable-au-moment-du-build-assets-config-app-config-json)
ci-dessous.

**Ajouter une nouvelle chaîne traduite** (processus) :
1. Rechercher dans `public/i18n/en.json` si une clé existe déjà sous `common.*` avant d'ajouter une
   nouvelle clé — ne jamais dupliquer.
2. Ajouter la clé dans `public/i18n/en.json` et `public/i18n/fr.json`, en les organisant par
   fonctionnalité/composant au lieu d'utiliser une clé plate en pointillés. Suivre les règles de
   namespace et de nommage définies dans `.github/instructions/i18n.instructions.md` (par exemple
   `<feature>.<component>.*`, `common.*`, `routes.*`, `aria-*`, `placeholder-*`).
3. Utiliser la clé dans les templates via `{{ 'key.path' | transloco }}` (ou
   `transloco: { param }` pour les valeurs interpolées), ou via
   `TranslocoService.translate('key.path')` en TypeScript lorsque le pipe n'est pas utilisable
   (voir [Exception connue](#exception-connue)).
4. Il n'existe pas d'étape d'extraction au moment du build ni de règle ESLint imposant la parité
   `en/fr` — une clé manquante s'affiche simplement en clair à l'exécution, donc vérifier les deux
   fichiers manuellement avant de valider.

**Autres points utiles :**
- Les fichiers JSON de traduction sont chargés paresseusement et sans bloquer le démarrage (voir
  [Branchement du bootstrap](#branchement-du-bootstrap-src-main-ts-src-app-app-config-ts)) — le
  premier rendu ne doit jamais attendre le réseau.
- Les titres de page (`<title>`) sont des clés de traduction résolues par une stratégie
  personnalisée `TitleStrategy` (voir [Titres de route](#titres-de-route-translocotitlestrategy)).
- `reRenderOnLangChange: true` est activé dans `main.ts`, donc le changement de langue à l'exécution
  re-render le composant sans rechargement complet de la page.

## Fichiers de traduction

Deux fichiers JSON, un par langue, organisés par fonctionnalité/composant :

```
public/i18n/en.json
public/i18n/fr.json
```

Le dossier est nommé `i18n` plutôt que `assets/transloco` parce que c'est la convention documentée
par Transloco (`TranslocoHttpLoader` charge `i18n/{lang}.json` par défaut). Il existe depuis avant
l'application et est conservé tel quel ; il n'a rien à voir avec l'i18n natif d'Angular. Voir
`src/transloco-loader.ts` pour l'implémentation du chargeur et
`.github/instructions/i18n.instructions.md` pour les conventions de nommage.

## Convention de nommage des clés de traduction (i18n)

Une stratégie de nommage a été mise en place pour éviter les doublons et maintenir la cohérence à
travers le projet.

### Structure

Les fichiers de traduction (`public/i18n/en.json` et `public/i18n/fr.json`) utilisent une
**structure hiérarchique imbriquée**, jamais plate :

```json
// ✅ Correct
{ "sections-tab": { "col-name": "Nom de section" }, "common": { "save": "Enregistrer" } }

// ❌ Interdit — ne pas aplatir le chemin dans une seule propriété
{ "sections-tab.col-name": "Nom de section" }
```

### Espaces de noms

| Namespace | Usage | Exemples |
|-----------|-------|----------|
| `common.*` | Texte générique réutilisable dans plusieurs fonctionnalités | `common.save`, `common.cancel`, `common.delete` |
| `routes.*` | Titres de page navigateur via `TranslocoTitleStrategy` | `routes.login`, `routes.study`, `routes.admin` |
| `shared.python-errors.*` | Messages d'erreur Python du moteur | `shared.python-errors.solver-error` |
| `shared.<service-name>.*` | Texte réutilisé par plusieurs composants ou généré par un service | `shared.obstacle-form-service.save-detail` |
| `<feature>.<component>.*` | Texte propre à un composant | `sections-tab.col-name`, `manual-section.tab-general` |

### Règles de construction des clés

- **Kebab-case** pour chaque segment : `sections-tab.col-name` et non `sectionsTab.colName`
- **Spécificité** : `supports-table.aria-chain-name` et non `supports-table.aria-1`
- **Libellés ARIA** : préfixe `aria-*` — `supports-table.aria-open-attachment-modal`
- **Placeholders** : préfixe `placeholder-*` — `sections-tab.placeholder-view-ic`
- **Notifications** : namespace `<feature>.notifications.*`
- **Erreurs de service** : `shared.<service-name>.*` — `shared.section-import.file-read-error`
- **Valeurs interpolées** : syntaxe `{{ param }}` —
  `"studio.conformity.calculation-failed-error": "Le calcul a échoué : {{ errorMessage }}"`

### Avant de créer une clé

**Toujours rechercher d'abord dans `en.json`** pour vérifier si une clé n'existe pas déjà. Si la
clé est dans `common.*`, la réutiliser au lieu de la dupliquer.

## Branchement du bootstrap (`src/main.ts` / `src/app/app.config.ts`)

- `provideTransloco()` est enregistré dans `main.ts` avec `availableLangs: ['en', 'fr']` et un
  `defaultLang: 'fr'` de secours.
- La langue active réelle est résolue à l'exécution par `AppConfigService.loadDefaultLang()` dans
  l'`APP_INITIALIZER` de `app.config.ts`, puis appliquée via `TranslocoService.setActiveLang()`.
- Le chargement du JSON de traduction (`TranslocoService.load()`) est intentionnellement non bloquant :
  il ne doit pas empêcher le premier rendu, car `i18n/*.json` passe par la même route protégée OIDC
  que les autres assets et peut être ralenti pendant une renegociation OIDC. Les composants lisent
  leurs traductions de manière réactive via le pipe `transloco`.

## Langue par défaut configurable au moment du build (`assets/config/app-config.json`)

`AppConfigService` lit `assets/config/app-config.json` (un fichier simple du type
`{ "defaultLang": "en" | "fr" }`) pour décider quelle langue activer.

Une copie de référence est commitée dans le dépôt dans `public/assets/config/app-config.json`
(`defaultLang: "fr"`), donc elle fonctionne directement en local.

Dans l'image Docker, ce fichier est régénéré au moment du build à partir de l'argument
`DEFAULT_LANGUAGE` (par défaut `fr`, défini dans `Dockerfile`), ce qui remplace la copie du dépôt :

```bash
RUN mkdir -p /usr/share/nginx/html/assets/config && echo "{\"defaultLang\": \"${DEFAULT_LANGUAGE}\"}" \
    > /usr/share/nginx/html/assets/config/app-config.json
```

Changer la langue pour un déploiement Docker nécessite donc de reconstruire l'image avec un autre
`--build-arg DEFAULT_LANGUAGE=...` — ce n'est pas un paramètre d'exécution dynamiquement modifiable.

- `AppConfigService.loadDefaultLang()` revient à `'fr'` avec un warning si le fichier est absent,
  invalide ou si la requête dépasse 3s (limite volontaire pour ne pas bloquer le premier rendu pendant
  l'initialisation de l'application).

## Titres de route (`TranslocoTitleStrategy`)

Transloco n'a pas d'intégration native avec `TitleStrategy` d'Angular Router. Les valeurs de
`title:` dans les routes sont interprétées comme des clés de traduction (namespace `routes.*`, par
exemple `routes.login`) et résolues par une stratégie personnalisée
`TranslocoTitleStrategy` (`src/app/core/strategies/transloco-title.strategy.ts`), enregistrée dans
`app.config.ts` via `{ provide: TitleStrategy, useClass: TranslocoTitleStrategy }`.

## Exception connue

`manualSection.component.ts` appelle `TranslocoService.translate(...)` de façon impérative au lieu
utiliser le pipe `| transloco` parce que les placeholders PrimeNG `p-paginator` (`{first}`,
`{last}`, `{totalRecords}`) entrent en conflit avec la syntaxe d'interpolation de Transloco. Voir le
commentaire `// TODO: STOP #2` dans `manualSection.component.html` et
`.github/instructions/i18n.instructions.md`.
