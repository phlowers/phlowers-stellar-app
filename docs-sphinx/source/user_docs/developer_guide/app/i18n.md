# Internationalization (i18n) — Transloco

Stellar uses [Transloco](https://jsverse.github.io/transloco/) for all user-facing text. Angular's
native i18n (`$localize`, `.xlf`, `i18n` attributes, `ng extract-i18n`) is not used anywhere in
this codebase.

## Synthesis

**Run locally:** nothing to configure — `public/assets/config/app-config.json` ships in the repo
with `defaultLang: "fr"` and is served as-is by `npm run start`/`ng serve`. Switch language at
runtime from the UI language selector, or edit that file manually to change the default.

**Run in Docker:** the default language is a build-time argument, baked into the image (changing it
requires rebuilding):
```bash
docker build --build-arg DEFAULT_LANGUAGE=en ...
```
See [Build-time configurable default language](#build-time-configurable-default-language-assets-config-app-config-json)
below.

**Adding a new translated string** (process/commands):
1. Search `public/i18n/en.json` for existing text/key under `common.*` before adding a new one —
   never duplicate.
2. Add the key to **both** `public/i18n/en.json` and `public/i18n/fr.json`, nested by
   feature/component (never a flat dot-joined property). Follow the namespace and naming rules in
   `.github/instructions/i18n.instructions.md` (e.g. `<feature>.<component>.*`, `common.*`,
   `routes.*`, `aria-*`, `placeholder-*`).
3. Use it in templates via `{{ 'key.path' | transloco }}` (or `transloco: { param }` for
   interpolated values), or via `TranslocoService.translate('key.path')` in TypeScript when a
   pipe isn't usable (see [Known exception](#known-exception)).
4. There is no build-time key-extraction step and no lint rule enforcing en/fr parity — a missing
   key just renders as the raw key string at runtime, so double-check both files manually (or grep
   for the key) before committing.

**Other features worth knowing:**
- Translation JSON is fetched lazily and non-blocking at startup (see
  [Bootstrap wiring](#bootstrap-wiring-src-main-ts-src-app-app-config-ts)) — first render never
  waits on the network.
- Route `<title>` values are translation keys, resolved by a custom `TitleStrategy` (see
  [Route titles](#route-titles-translocotitlestrategy)).
- `reRenderOnLangChange: true` is set in `main.ts`, so switching language at runtime re-renders the
  whole app without a reload.

## Translation files

Two JSON files, one per language, nested by feature/component:

```
public/i18n/en.json
public/i18n/fr.json
```

The folder is named `i18n` (not `assets/transloco` or similar) because this is Transloco's own
documented default convention (`TranslocoHttpLoader` fetches `i18n/{lang}.json` by default) — it
predates the app and is kept as-is, it is unrelated to Angular's native i18n system. See
`src/transloco-loader.ts` for the loader implementation and
`.github/instructions/i18n.instructions.md` for key-naming conventions.


## Translation Key Naming Convention (i18n)

A translation naming strategy has been established to avoid duplication and maintain consistency across the project.

### Structure

Translation files (`public/i18n/en.json` and `public/i18n/fr.json`) use a **hierarchical nested structure**, never flattened:

```json
// ✅ CORRECT
{ "sections-tab": { "col-name": "Section Name" }, "common": { "save": "Save" } }

// ❌ FORBIDDEN — never store the path as a single flattened property
{ "sections-tab.col-name": "Section Name" }
```

### Namespaces

| Namespace | Usage | Examples |
|-----------|-------|----------|
| `common.*` | Generic text reused across multiple features | `common.save`, `common.cancel`, `common.delete` |
| `routes.*` | Browser tab titles (via `TranslocoTitleStrategy`) | `routes.login`, `routes.study`, `routes.admin` |
| `shared.python-errors.*` | Python engine error messages | `shared.python-errors.solver-error` |
| `shared.<service-name>.*` | Text reused by multiple components or produced by a service | `shared.obstacle-form-service.save-detail` |
| `<feature>.<component>.*` | Text specific to a single component | `sections-tab.col-name`, `manual-section.tab-general` |

### Key Construction Rules

- **Kebab-case** for each segment: `sections-tab.col-name` not `sectionsTab.colName`
- **Specificity**: `supports-table.aria-chain-name` not `supports-table.aria-1`
- **Aria labels**: prefix `aria-*` — `supports-table.aria-open-attachment-modal`
- **Placeholders**: prefix `placeholder-*` — `sections-tab.placeholder-view-ic`
- **Notifications**: namespace `<feature>.notifications.*`
- **Service errors**: `shared.<service-name>.*` — `shared.section-import.file-read-error`
- **Interpolated values**: syntax `{{ param }}` — `"studio.conformity.calculation-failed-error": "Calculation failed: {{ errorMessage }}"`

### Before Creating a Key

**Always search in en.json** to see if the key already exists. If it is under `common.*`, reuse it — never duplicate.

## Bootstrap wiring (`src/main.ts` / `src/app/app.config.ts`)

- `provideTransloco()` is registered in `main.ts` with `availableLangs: ['en', 'fr']` and a
  build-time fallback `defaultLang: 'fr'`.
- The actual active language is resolved at runtime by `AppConfigService.loadDefaultLang()`
  (called from the `APP_INITIALIZER` in `app.config.ts`) and applied via
  `TranslocoService.setActiveLang()`, overriding the `fr` fallback.
- The translation JSON fetch itself (`TranslocoService.load()`) is fire-and-forget: it must never
  block first render, since `i18n/*.json` goes through the same OIDC-protected route as any other
  asset and can stall during an OIDC renegotiation. Components read translations reactively
  through the `transloco` pipe, which loads on demand.

## Build-time configurable default language (`assets/config/app-config.json`)

`AppConfigService` fetches `assets/config/app-config.json` (a plain
`{ "defaultLang": "en" | "fr" }` file) to decide which language to activate.

A default copy is checked into the repo at `public/assets/config/app-config.json` (`defaultLang:
"fr"`), so it is part of the build output and works out of the box in local development.

In the Docker image, this file is regenerated at **build time** from the `DEFAULT_LANGUAGE` build
arg (default `fr`, `Dockerfile`), overwriting the checked-in copy:
```
RUN mkdir -p /usr/share/nginx/html/assets/config && echo "{\"defaultLang\": \"${DEFAULT_LANGUAGE}\"}" \
    > /usr/share/nginx/html/assets/config/app-config.json
```
Changing the language for a Docker deployment therefore requires rebuilding the image with a
different `--build-arg DEFAULT_LANGUAGE=...` — it is not a per-container runtime override.
- `AppConfigService.loadDefaultLang()` falls back with log warning to `'fr'` if the file is absent,
  malformed, or the request exceeds a 3s timeout (bounded on purpose — see incident 2026-08-10:
  `APP_INITIALIZER` blocks initial navigation, so a hung request must not blank first render).


## Route titles (`TranslocoTitleStrategy`)

Transloco has no built-in integration with Angular Router's `TitleStrategy`. Route `title:` values
are treated as translation keys (namespace `routes.*`, e.g. `routes.login`) and resolved by a
custom `TranslocoTitleStrategy` (`src/app/core/strategies/transloco-title.strategy.ts`), registered
in `app.config.ts` via `{ provide: TitleStrategy, useClass: TranslocoTitleStrategy }`.

## Known exception

`manualSection.component.ts` calls `TranslocoService.translate(...)` imperatively instead of using
the `| transloco` pipe, because the PrimeNG `p-paginator`'s `{first}`/`{last}`/`{totalRecords}`
placeholders conflict with Transloco's own interpolation syntax. See the `// TODO: STOP #2` comment
in `manualSection.component.html` and `.github/instructions/i18n.instructions.md`.
